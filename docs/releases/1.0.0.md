## User-visible features

- Original V6 six-window spatial world, global camera, radial constellation/task branches, urgency and completion views, timeline and milestones.
- Dated paper journal with formatted pages, timeline markers, date editing, Markdown export, safe HTML handling and Undo.
- Drag/resize and keyboard/touch controls, responsive navigation, reduced-motion and the M2.5 motion fixes.
- CSV tasks and V5/V6-compatible complete JSON import/export.
- Protected owner password sign-in; cloud-backed owner snapshots, revision-aware sync/conflict recovery, explicit import consent and backup.

This is **not** a multi-user product release; Issue #4 multi-user plans, reminders, calendar/Classroom integration, rich attachment storage or a new editor were not added here.

## Important acceptance limits

- Hosted **PATCH/DELETE via a real nonowner bearer token** has **not** been run; local HTTP tests are not a hosted substitute.
- Real authenticated application **CSP/headers after Vercel Authentication** have not been independently captured. An SSO redirect with no CSP header is not evidence that the application's own headers are wrong.
- Physical Safari/Android/120 Hz/assistive-technology testing and optional Google OAuth/Email OTP delivery remain unverified.
- Owner reports a saved private full JSON backup; restore and storage encryption were not independently checked. JSON export itself is unencrypted.
- This was a focused security and release verification effort, not a comprehensive third-party penetration-test certification.
- Supabase's leaked-password protection warning requires a paid tier; no upgrade was purchased or required for this private release. Keep strong owner credentials and restricted account enrollment.

## Operating and rollback guidance

Normal use: **[orbit.starscene.com](https://orbit.starscene.com/)**. Secondary address redirects to that hostname because the app rejects sign-in from a different origin. Vercel Authentication and server owner RLS must stay enabled. Existing code/aliases were verified in the release tracker, not through a blanket automatic `vercel promote`.

For a future release, use the [operations runbook](../OPERATIONS.md): backup, review source SHA, run CI, stage under real Production config with `--skip-domain`, verify protection, then reassign only approved aliases. The previous legacy deployment is recorded for emergency reference but is not automatically certified as functionally known-good. Alias rollback **does not restore database data**.

More detail: [project history](../PROJECT_HISTORY.md) and [M6 decision/evidence issue](https://github.com/DoorBlox/orbit/issues/2).
